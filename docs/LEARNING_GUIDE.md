# 学习路线与练习方式

建议先打开 [来源核验](SOURCE_MAP.md)，再从 [章节索引](CHAPTERS.md) 选择章节。
原书说明代码采用语言无关的伪代码；本项目将学习目标落实为可编译的原创 Java 17 场景，而非逐行移植。

## 建议路线

1. 第 01-03 章：认识对象、封装、继承、多态，以及依赖/关联/聚合/组合。能够从角色说清状态由谁拥有。
2. 第 04-09 章：先识别变化，再判断抽象是否值得。用新增实现和修改客户代码的范围衡量设计，而非统计模式数量。
3. 第 10-14 章：SOLID。重点读测试中的替换契约、接口能力和依赖注入，不机械追求类越多越好。
4. 第 15-19 章：创建型。比较创建单个产品、创建产品族、分步骤构造、复制对象、限制实例数量。
5. 第 20-26 章：结构型。比较兼容旧接口、拆分变化维度、树形聚合、包装功能、简化子系统、共享状态和控制访问。
6. 第 27-36 章：行为型。关注请求流转、撤销、遍历、协作路由、快照、事件通知、状态转换及操作扩展。

## 每章的一次学习循环

先读本章来源标记与学习目标，再运行示例预测输出；从 demo 沿接口走进实现，为每个对象标注模式角色。
阅读测试，找出至少一个状态断言和一个边界或失败情形。之后完成本章的两个具体扩展任务，并新增测试。
最后重跑本章测试及全量测试，用自己的话解释：变化点是什么、替换契约是什么、引入了什么成本。

所有章均有已完成的参考实现和三项基线测试。笔记中的任务是可选学习扩展，不会导致初始构建失败。
任务没有预先写成失败测试，以免无法直接运行项目；可以在 IDE 中折叠参考实现，先自行实现后再对照。
各章互相独立，相近类名出现在不同包中是为便于单章复制学习，刻意不抽取跨章节业务框架。

## 容易混淆的模式

| 对比 | 先问的问题 |
|---|---|
| 工厂方法 / 抽象工厂 | 创建一种产品，还是一组必须配套的产品？ |
| 生成器 / 原型 | 逐步构造，还是从已有状态复制？ |
| 适配器 / 桥接 | 接入不兼容旧接口，还是预先拆开两个变化维度？ |
| 装饰 / 代理 | 增加可叠加职责，还是控制访问？ |
| 策略 / 状态 | 客户选择算法，还是对象生命周期驱动转换？ |
| 命令 / 备忘录 | 保存动作与逆操作，还是保存不透明的状态快照？ |
| 策略 / 模板方法 | 通过组合替换算法，还是通过继承替换骨架中的步骤？ |

## 结语：扩展原创复盘

PDF 的 Conclusion 只有目录，以下是本项目自己的结课任务：
选择一个日常业务，先给出最直接实现；制造两种真实需求变化，再决定是否应用 1-2 个模式。
提交行为测试、修改范围比较和代价说明。能解释不用模式的理由，也是学习成果。

## 练习边界

示例只在内存中运行。除枚举单例访问测试外，不假定并发安全；代理、享元、观察者等的线程与错误策略在各章有单独说明。
本项目不引入 Spring，不连接数据库，不访问网络。Maven 下载构建依赖时需要网络或已有本地缓存。
